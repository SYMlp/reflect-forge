# 日报：变化先行，证据后置

## 判据

- 日报的头条是变化，不是清单——「先比较今天和昨天有什么变化」，再说这个变化为什么重要。
- 完成项不是主角，只作后置证据，用来支撑开头写的那条变化。
- 「证据不足就明确写待确认」——宁可保留不确定性，也不猜测填补；证据缺到哪一档，就降到哪一档的写法，不许因为缺料就整段跳过或硬编。
- 「每次改模板要留一行 why」——写清触发事件和取舍，不许静默改。

## 步骤

1. 收料：拉出今天的工作记录和昨天的日报（或昨天的记录），并排列出两天的差异点，产出一份「今昨差异清单」。昨天的料缺失时按序降级取料：最近一份日报 → git log / 聊天记录 / 日历等旁证 → 都没有就以「上次有记录的状态」为比较基线；用了哪一档，在差异清单顶部标一行来源。
2. 定头条：从差异清单里挑出最重要的 1-2 条变化，写成日报开头——每条包含「变化是什么 + 它为什么重要」两个半句，缺一不可。
3. 挂证据：把今天的完成项逐条挂到对应变化下面，作为支撑证据；挂不上任何变化的完成项放到末尾简列，不展开。
4. 标缺口：逐条检查写下的判断，按证据缺口分档降级：① 有记录但没核实 → 句尾加「（待确认）」；② 只有旁证（聊天、口头、记忆）→ 改写成「据 X（待确认）」并注明来源；③ 完全拿不出支撑 → 不写成结论，改为事实性描述或移入末尾「存疑区」单列。任何一档都不许用推测替代。
5. 留痕（仅当这次动了日报模板/结构时）：在日报末尾或模板文件里附一行 why——是什么事触发了这次改动、为此舍弃了什么。

## 反例

- 开头堆「今天完成了 A、B、C」的流水清单，而不是先说今昨之间变了什么、为什么值得看。
- 数据没核实就写成确定语气的结论，而不是老老实实标「待确认」。
- 发现昨天的记录缺了，就干脆跳过今昨比较直接堆完成项，而不是按降级路径换旁证或换基线再比。
- 悄悄调整了日报的结构或模板就直接交，而不是附一行 why 说清触发事件和取舍。
