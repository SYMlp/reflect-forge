# 回炉单生成器 · Charge Sheet —— 炉子的进料口

> 反思炉把 session 里的精华（铁）锻成剑。但**反思本身有入场成本**：要想起来开、
> 要自己找料、要自己组织问题。回炉单生成器把「找料 + 归集」这一段自动化。
>
> 它是一台**确定性归集器，不是判断器**——只数、只归、只排序，
> 含金量判断留给反思炉和反思会话（判断给 LLM、归集给程序，这是设计原则）。

## 干什么

`python charge_sheet.py` 读两处只读数据源，按**两根轴**把使用痕迹归成一份「回炉单」：

| 数据源 | 路径（进 config.json `charge_sheet` 键，不硬编码） | 取什么 |
|:--|:--|:--|
| hook 路由台账 | `charge_sheet.ledger_path` | 每条 prompt 的命中/miss（组件轴） |
| session 转写 | `charge_sheet.session_glob` | assistant 文本里「本场一件事：」申报（事轴） |

产出落 `data/charge/`：`charge-<日期>.md`（人读）+ `charge-<日期>.json`（机读）+ `charge-latest.*`（最新指针）。

回炉单四节：
1. **组件轴** —— 每个 route/组件的命中次数、时间跨度、代表性开场样本。
2. **开场 miss 区** —— matched 为空的**开场**行（已滤 task-notification 等系统噪声，滤掉几条照实报）。这些是「该有设计到场却裸奔」的重点矿。会话**中途**的无命中行单独计数附少量样本——中途 prompt 多数本就无需路由到场，不算裸奔。
3. **事轴** —— sid → 「本场一件事」申报（有标记的列出来，无标记的计数）。
4. **候选淬火排序** —— 按命中频次等确定性指标排个先后。**只排序，不下结论。**

**开场判定（2026-09-01 首炉修订）**：台账按 append 时序落行，某 sid 在**全量台账**里的第一行即该会话的开场——first-seen 跨全文件计算，不受 `--since` 影响（窗前开的场，窗内的行算中途）。缺 sid 的行无法 sessionize，保守按开场计。这是机械事实归集，不是含金量判断，故留在生成器侧。修订缘起：首版把中途短 prompt（"动吧。"/"b"）也计成裸奔开场，miss 密度虚高到 0.625；分层后同窗读数为开场 0/3 裸奔 + 中途 22 条——两个口径讲的是两件事。

## `--since <YYYY-MM-DD>`：日期切窗

台账混着路由上线前的老行，会把 miss 密度虚高地拉起来（首版实测 0.811）。首炉只想看
「设计上线后」的裸奔率时，用 `--since` 切掉窗前老账：

```
python charge_sheet.py --since 2026-09-01
```

语义（**两根轴同窗**）：

- **组件轴 + miss 区**：只统计台账里 `ts >= since` 的行。无法解析 `ts` 的行——因为定位不了时间、也就无法确认在窗内——一并剔除。
- **事轴（session 侧）**：按会话时刻 `>= since` 过滤，窗外的整份不扫、不计数（`total_sessions` 也只算窗内）。
  - **会话时刻怎么取（择一说明）**：优先取 session jsonl 里**首个可解析的消息 `timestamp`**；整份取不到才退回**文件 mtime**。
  - **为什么选首个 timestamp**：jsonl 按 append 时序落行，首行即开场，所以「首个 timestamp = 开场时刻」。窗口语义是「设计上线后**开的**场」，按开场时刻归窗最贴切；mtime 是最后修改（≈ 收尾）时刻，只当兜底。（此择一 2026-09-01 用户已认可，非 AI 单方选择。）
- **头部标注**：传了 `--since` 时，回炉单头部会多一行 `窗口：<日期> 起（--since）`；**不传 `--since` 时产物与从前逐字节一致**。

时区小注：session `timestamp` 是 UTC（带 `Z`），台账 `ts` 是本地朴素时间。为让两侧同尺子比较，程序统一丢时区、按朴素时间比。因此跨零点 ~8h 内的边界场次可能落错一侧——窗口只到「天」的粒度，这点偏差可接受。

`--selftest` 已覆盖窗口过滤：窗内计入 / 窗前剔除（消息 ts 与 mtime 兜底两条路径）/ 不传参数行为不变。

## 硬边界

- **本文件里没有一次 LLM 调用**。它跟 `main.py` 的反思炉/锻剑炉不同——那两处调 `claude` CLI 做判断，这里一行不调。
- session 转写可能十几 MB：**逐行流式解析**，先对原始行做廉价子串判断，marker 不在才不解析——绝不整文件载入。
- 台账 sid 截断到 16 字符，session 文件名是完整 uuid；两轴靠**文件名前 16 位 = 台账 sid** 缝合。
- `python charge_sheet.py --selftest`：临时目录造数据自测（含命中聚合 / 噪声过滤 / 申报缝合 / 双版落盘 / `--since` 窗口过滤，全套断言），不依赖真实数据。
